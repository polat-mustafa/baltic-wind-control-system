Open source · Offshore wind engineering · Southern Baltic

An offshore wind farm you can operate.

OffshoreForge takes a 510 MW Baltic wind farm through its whole life — from an empty patch of sea to the last turbine coming down. Every screen is a working engineering model, and every model is checked against measurements, standards or a hand calculation.

02 — Lifecycle

Forty years of a wind farm, one model.

Each phase hands its results to the next: the layout sets the cable lengths, the cables set the reactive power, the grid study sets the protection, and the same turbine model runs in the SCADA, the forecast and the digital twin. Pick a phase to open it in the demo.

04 — The case

SB-510, Southern Baltic.

One reference project, modelled on the Polish Baltic build-out: a real spatial-plan basin, real bathymetry, a real grid connection point. The physics and the engineering are real; the farm itself is fictional.

05 — How it is built

Engineering engines behind a web interface.

The physics runs in Python on the open-source engines the industry itself uses; the browser draws it. Nothing on the screen is a hard-coded number that a model did not produce.

Interface

  • React 19 · TypeScript (strict)
  • MapLibre + deck.gl charts of the sea
  • three.js turbine with the ROSCO controller
  • Plotly · XYFlow single-line diagrams
  • English · Turkish

Engines

  • FastAPI · Python 3.13 · Pydantic v2
  • PyWake — wakes and energy yield
  • pandapower — load flow, IEC 60909
  • ANDES — fault ride-through dynamics
  • XGBoost · PyTorch LSTM / TFT forecasts
  • asyncua — OPC UA server

Platform

  • PostgreSQL 16 + TimescaleDB · Redis
  • Docker Compose — one command
  • ≈ 1 500 backend tests, typed, linted
  • GitHub Actions CI · MkDocs handbook
  • Every method traced to its source
